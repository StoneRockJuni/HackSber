# QR-маркер полётного задания: как это должно работать

Документ описывает идею, текущее состояние кода, инженерные ограничения (с
замерами) и план внедрения. Для защиты и для передачи в разработку.

---

## 1. Зачем вообще QR, если есть GPS и EXIF

Заказчик на Q&A подтвердил: **дрон не подписывает снимки**, а у части кадров
метаданных нет вообще. Значит нужно чем-то доказать две вещи:

1. **Где** снято (координата) — это даёт GPS/EXIF, но его можно подделать.
2. **Когда и по какому заданию** снято — этого GPS не даёт вообще.

QR-маркер решает вторую задачу. Идея: перед вылетом подрядчик получает
**одноразовый код**, кладёт его на участке и снимает в кадре. Если код в кадре
есть — значит снимок сделан **для этой проверки** и **в это окно времени**, а не
найден в интернете и не взят из прошлогоднего облёта.

Это дешёвая замена подписи: печать листа стоит копейки, а криптографии на
стороне дрона не требует.

## 2. Что есть в коде сейчас (честно)

| Элемент | Где | Состояние |
|---|---|---|
| Поиск QR в кадре | `security._decode_qr_codes` | **работает**: `cv2.QRCodeDetector().detectAndDecodeMulti` |
| Сверка с ожидаемым | `security.check_challenge_marker` | **работает**, но сравнение — простая строка (casefold) |
| Где задаётся ожидание | сайдбар `QR-маркер полётного задания` | **демо-заглушка**: текст вводит человек, по умолчанию `STROYKONTUR-DEMO-2026` |
| Источник отметки | `_meta.marker_source` | `qr` / `exif_fallback` / `none` |
| Влияние на решение | `security.evidence_level` | `qr` → уровень `strong` |
| Цветной маркер | `_parse_color_marker`, `_has_color_marker` | демо-заглушка, помечена как таковая |

**Чего нет:** выдачи маркеров, срока жизни, одноразовости, подписи, привязки к
кадастровому объекту, хранения использованных токенов, страницы «сгенерировать
маркер задания». То есть проверка есть, а **процесса вокруг неё нет**.

## 3. Предлагаемый процесс (как это должно работать)

```
БАНК                    ПОДРЯДЧИК                     СИСТЕМА
 │                            │                          │
 │ 1. создаёт полётное        │                          │
 │    задание (объект, дата)  │                          │
 ├───────────────────────────>│ 2. получает PDF/PNG      │
 │    одноразовый маркер      │    маркера (печать)      │
 │                            │                          │
 │                            │ 3. кладёт лист на участок│
 │                            │    (на землю/на забор)   │
 │                            │                          │
 │                            │ 4. снимает: облёт +      │
 │                            │    кадр с маркером       │
 │                            ├─────────────────────────>│ 5. декодирует QR
 │                            │                          │ 6. проверяет подпись,
 │                            │                          │    срок, одноразовость,
 │                            │                          │    объект
 │                            │                          │ 7. пишет в аудит
 │<──────────────────────────────────────────────────────┤    marker_payload,
 │                                                        │    marker_verified
```

Ключевая деталь: **кадр с маркером не обязан показывать весь дом**. Достаточно,
чтобы маркер был в кадре и был привязан к тому же полётному заданию (номер,
время, GPS рядом с объектом). Дом оценивается по остальным кадрам серии.

## 4. Формат маркера

Содержимое QR (payload) — компактная строка с подписью:

```
SC1|FT-2026-11-01-001|54:19:133701:2991|1730000000|a7f31c9e|8f1c2a5e9d4b7c3a6f0e2d5c8b1a4f7e
 │   │                  │                  │          │        │
 │   │                  │                  │          │        └ HMAC-SHA256 (16 hex) по первым полям
 │   │                  │                  │          └ nonce (8 hex), одноразовый
 │   │                  │                  └ expires_at (unix time), например +2 часа
 │   │                  └ кадастровый номер объекта залога
 │   └ ID полётного задания
 └ версия формата
```

Правила проверки (`verify_marker`):

1. `SC1` — версия формата поддерживается;
2. HMAC совпадает (ключ банка, не в QR);
3. `expires_at` ещё не истёк (TTL 2–6 часов: полёт не длится дольше);
4. `nonce` не встречался раньше (таблица использованных);
5. кадастровый номер в маркере = объект, по которому принимается решение;
6. задание `FT-...` существует и выдано этому подрядчику.

Только после этого `evidence_level = strong`. Любая ошибка → `weak`/`none` и
причина в объяснении.

Почему HMAC, а не просто случайная строка: чтобы нельзя было **напечатать свой
QR** с любым номером объекта. Без ключа подпись не сделать.

Почему short-формат, а не URL: чем короче payload, тем меньше модулей в QR, тем
крупнее можно снимать (см. §5). URL оставляем как вариант для печати на
человека — рядом мелким текстом «что это и куда звонить».

## 5. Сколько пикселей нужно QR и какого размера печатать

Наш замер (OpenCV 5, `cv2.QRCodeEncoder`, JPEG q90, реальный фон с дрона):

| Payload | Модулей | Минимальный размер, при котором **читается** |
|---|---|---|
| `FT-2026-11-01-001` (17 символов) | 25×25 | **от 80 px** |
| `SC1\|FT-…\|кадастр\|exp\|nonce` (56 символов) | 37×37 | **от 120 px** |
| длинный URL с подписью (88 символов) | 41×41 | от 80–120 px |

Ниже 80 px QR не читается вообще — это не «плохо читается», а «нет».

Теперь переводим пиксели в метры. Для камеры DJI M3M (5280 px по горизонтали,
горизонтальный угол ~73°):

**пикселей на метр ≈ 3569 / высота_полёта**

| Высота | px на метр | Нужный размер для 120 px | Для 80 px |
|---|---|---|---|
| 10 м | 357 | **0,34 м** (лист A3) | 0,22 м (A4) |
| 20 м | 178 | **0,67 м** (плакат A1) | 0,45 м (A2) |
| 40 м | 89 | **1,35 м** (баннер 1,5×1,5 м) | 0,90 м |
| 60 м | 59 | 2,0 м | 1,35 м |

**Вывод, который надо проговорить:** обычный QR на листе A4 читается только с
10–12 метров. На рабочей высоте облёта 40 м нужен **баннер ~1,3×1,3 м** или
отдельный кадр с малой высоты.

Отсюда два практичных варианта процесса:

* **Вариант А (дешевле):** подрядчик делает обычный облёт (40–60 м) + один
  кадр с 8–12 м, где виден маркер A3/A4. Кадров с маркером достаточно одного-двух.
* **Вариант Б (удобнее для съёмки):** банк печатает складной баннер 1,5×1,5 м
  (или мат из ПВХ), подрядчик возит его с собой и кладёт на участке.

Что учесть при печати:

* **тихая зона** (белая рамка) вокруг QR — минимум 4 модуля, иначе не читается;
* **матовая** поверхность: глянец ловит блик и «сжигает» код;
* **грузик** (кирпич/скотч): ветер переворачивает лист;
* **контраст**: не печатать на зелёной траве без белой подложки;
* **ориентация**: QR должен быть «лицом» к камере, без сильного наклона >45°;
* **не накрывать** маркером дом — он должен быть рядом, в углу кадра.

Изменения в существующем коде:

* `check_challenge_marker` → вместо сравнения строк вызывает `verify_marker`;

Для пилота — таблица в БД банка с уникальным индексом по `nonce`.

## 7. Что маркер доказывает, а что нет

| Утверждение | Доказывает? |
|---|---|
| «Снимок сделан по этому полётному заданию» | ✅ да, если подпись и задание сошлись |
| «Снимок сделан в окне времени задания» | ✅ да, TTL + одноразовость |
| «Снимок сделан у этого объекта» | ⚠️ частично: маркер привязан к объекту, но физически его могли положить в другом месте — поэтому нужен ещё GPS/кадр местности |
| «Снимок сделан именно дроном» | ❌ нет: маркер можно снять телефоном |
| «Маркер не перепечатан с прошлого раза» | ✅ да, если nonce одноразовый и TTL короткий |

Последний пункт — почему TTL и одноразовость важнее самой картинки: фотографию
QR можно хранить годами, а токен с истечением — нет.

## 8. Угрозы и контрмеры

| Атака | Контрмера | Остаток |
|---|---|---|
| Сфотографировать QR в другом месте | QR привязан к объекту; в кадре должны быть признаки участка; GPS кадра | подрядчик может физически привезти маркер на другой участок — нужен выборочный контроль |
| Взять QR с прошлого задания | TTL + одноразовый nonce | если задание ещё действительно, токен валиден — это нормально |
| Напечатать свой QR | HMAC-подпись ключом банка | ключ нужно хранить в секрет-менеджере |
| Вклеить QR в фотошоп | хэш файла + артефакты сжатия + несколько кадров | специально сделанную вклейку детектировать сложно — нужен ручной выборочный разбор |
| Снять QR с экрана телефона | размер и перспектива, тени, блики — эвристики | не гарантия |
| Заменить маркер после съёмки | маркер должен быть в сцене вместе с объектом | — |

Честный вывод: QR — это **организационно-техническая** мера, а не криптография
на борту. Он сильно поднимает цену подделки, но не делает её невозможной.

## 9. Альтернативы, если заказчик скажет «QR неудобно»

| Вариант | Плюсы | Минусы |
|---|---|---|
| **ArUco / AprilTag** | устойчивее к ракурсу и масштабу, детектится на большем расстоянии, есть готовый генератор в OpenCV | нужен свой словарь и чуть больше возни с печатью |
| **Динамический код на экране телефона подрядчика** | меняется каждые 30 с — сильнее любого статичного QR | нужен интернет/приложение у подрядчика |
| **Цветной маркер** (уже есть заглушка) | дешевле всего | легко подделать, слабая защита |
| **ЭП подрядчика на акте приёмки** | юридически весомо | не привязано к кадру |
| **Аппаратная подпись/лог дрона** | самое сильное | зависит от модели и прошивки, у заказчика её нет |
| **Два независимых канала** (QR + GPS + время) | дешёвая комбинация, уже реализована | требует дисциплины подрядчика |

Рекомендация: **QR сейчас** (дёшево, работает без интернета), **ArUco** — как
следующий шаг для дальних кадров, **ЭП подрядчика** — организационно.

## 10. Что сказать на защите (30 секунд)

> «Дрон не подписывает снимки, поэтому мы вводим одноразовый QR-код на полётное
> задание. Подрядчик получает его перед вылетом, кладёт на участок и снимает в
> кадре. Код содержит номер задания, кадастровый номер объекта, срок действия и
> подпись ключом банка. Система проверяет подпись, срок и то, что код не
> использовался раньше — и только тогда считает снимок доказанным. Мы замерили:
> обычный QR читается с 10–12 метров, поэтому либо печатаем баннер 1,3 метра для
> съёмки с 40 метров, либо делаем один дополнительный кадр с малой высоты».
