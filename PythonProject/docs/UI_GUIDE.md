# Разбор интерфейса «СтройКонтур» до мелочи

Документ отвечает на вопросы: «откуда эти цифры?», «что значит каждая плашка?»,
«что происходит, когда я нажимаю кнопку?». Читать с открытым приложением
(`run.bat`).

---

## 1. Верхняя панель KPI (4 плитки)

Это витрина для жюри, а не живые данные банка. Важно честно понимать, что
откуда берётся.

| Плитка | Значение | Откуда | Честный комментарий |
|---|---|---|---|
| **Портфель ИЖС Сибирского банка** | `17 800 кредитов` | **зашито в код** (`app.py`, строка `k1.metric`) | цифра из кейса (`Кейс_3.md`: «в портфеле Сибирского банка 17,8 тыс. кредитов ИЖС»). Не из базы |
| ↳ подпись | `Контроль 3–5 раз за цикл` | зашито | тоже из кейса: проверки проводятся 3–5 раз за жизнь кредита |
| **Скорость осмотра 20 объектов** | `1 день (БПЛА)` | зашито | из кейса: 20 объектов силами сотрудников — 2 недели, с БПЛА — 1 день |
| ↳ дельта | `-13 дней (ускорение в 14 раз)` | зашито | арифметика: 14 дней − 1 день = 13; 14 / 1 = 14 раз. Считается вручную, не в коде |
| **Выбранный кадастровый участок** | например `54:19:133701:2991` | **из реестра** | берётся из выбранной строки `Реестр_для_теста.xlsx` |
| **Плановый срок завершения** | например `27.02.2028` | **из реестра** | колонка `Плановая дата` |
| ↳ дельта | `ПЗ: Нет` | **из реестра** | колонка `Наличие ПЗ`; зелёная стрелка вверх = «просрочки нет» |

> На защите так и говори: «первые две плитки — целевые KPI из кейса, вторые две
> — живые данные из реестра участков». Если сказать «это из системы банка», а
> спросят про интеграцию — поплывёшь.

## 2. Что такое ПЗ (и остальные поля реестра)

**ПЗ = просроченная задолженность** — клиент не внёс платёж вовремя (просрочил
кредит). В реестре это колонка `Наличие ПЗ` со значениями `Да` / `Нет`.

Почему это важно: от ПЗ зависит, какая стратегия выбирается. Нет просрочки и
стройка идёт → плановый мониторинг. Есть просрочка → урегулирование или суд.
Есть просрочка + срок истёк + ничего не построено → взыскание.

Полный список колонок `Реестр_для_теста.xlsx` (34 участка):

| Колонка | Что значит | Что с ней делает система |
|---|---|---|
| `Территория` | адрес участка | показывается в карточке досье и в Акте |
| `Кадастровый номер` | уникальный номер участка в ЕГРН | показывается и пишется в акт/аудит |
| `Плановая дата` | к какому сроку дом должен быть готов | расчёт остатка срока, просрочки |
| `Фактическая дата` | когда реально завершили (в тестовом файле везде `Нет`) | **не используется** (задел на будущее) |
| `Наличие ПЗ` | просроченная задолженность: Да/Нет | ключевой флаг для стратегий 2, 6, 8 |
| `ОН зарегистрирован` | объект недвижимости поставлен на кадастровый учёт | влияет на стратегию 7 (в тестовом файле у всех `Нет`) |
| `Залог` | оформлен ли залог банка | тоже стратегия 7 (у всех `Нет`) |
| `Дата начала строительства` | когда начали | база для «доли истёкшего срока» |
| `Наличие фото с неба` | есть ли аэрофото | **не используется** (предполагается, что фото грузим мы) |

Важный побочный эффект: раз в тестовом реестре у **всех** `ОН зарегистрирован =
Нет` и `Залог = Нет`, то любой дом на 100 % получит **стратегию 7** («поставьте
на учёт и оформите залог»). Это не баг, а свойство тестовых данных — и хорошая
демонстрация: система замечает, что дом достроен, но банк ещё не оформил залог.

## 3. Левая колонка: «AI-Агент «Глаз»»

### 3.1. Загрузка снимков

`Загрузите аэрофотоснимки объекта… (поддерживается пакетная загрузка)` —
можно перетащить один файл или серию кадров (до 24 анализируются, остальные
показываются в превью). Форматы: JPG, JPEG, PNG.

Сразу под загрузчиком — **превью до 4 кадров** с именем файла. Это просто
картинки, на решение не влияют.

### 3.2. Паспорт снимка (создаётся в фоне)

Для **первого** файла строится JSON-паспорт:

* `client_id = CL-0042` — **псевдоним**, не ФИО (ПДн не храним);
* `drone_id = DJI-M3M-DEMO`, `flight_task_id = FT-2026-10-31-042`,
  `operator_id = contractor-demo` — в демо зашиты, в пилоте приходят из
  полётного задания;
* `hash.value` — SHA-256 всех байтов файла;
* `gps`, `exif` — что нашли в файле;
* `verification_url` — ссылка для проверки паспорта;
* `custody` — цепочка: capture → passport_created.

### 3.3. Четыре синие плашки (метаданные)

| Плашка | Что показывает | Как читать |
|---|---|---|
| **Комплектация** | `Тип А (полный EXIF + GPS)` / `Тип Б (GPS из полетного лога)` / `Метаданные отсутствуют` | какая комплектация данных пришла (это ровно термины из кейса) |
| **GPS Снимка** | `54.85…, 83.19…` или `None` | координаты из самого файла. `None` = координат нет, и это не ошибка программы |
| **Резкость (Laplacian)** | число, норма `> 120` | дисперсия лапласиана: «размытость». Меньше 120 → кадр брак |
| **SHA-256** | первые 16 символов | «отпечаток» файла; полный хэш — в подписи ниже |

### 3.4. Строка про QR-маркер

Если в сайдбаре задан ожидаемый маркер, появляется строка:
`QR-маркер STROYKONTUR-DEMO-2026: подтверждён/не найден (источник: qr/exif_fallback/none)`.

* `qr` — нашли настоящий QR в кадре;
* `exif_fallback` — QR не нашли, но есть EXIF, и включён **демо-режим** (EXIF
  считается сигналом свежести);
* `none` — ни того, ни другого.

### 3.5. Строка про нейросеть

`AI: YOLOv8n SberStroi · классов проанализировано: N · классы: … · уверенность
стадии: 0.89 · согласованность серии: 1.0 · модель SHA-256: …`

* «классов проанализировано» — сколько кадров реально прогнали (до 24);
* «классы» — что нашлось (только те, что выше порога);
* «уверенность стадии» — 0…1; ниже 0.75 → решение не автоматическое;
* «согласованность серии» — какая доля кадров дала ту же стадию;
* «модель SHA-256» — отпечаток файла нейросети (защита от подмены весов).

### 3.6. «🔎 Диагностика: откуда GPS и почему такой вердикт»

Раскрывающийся JSON: `gps_source`, `has_exif`, координаты, дата EXIF, модель
дрона, SHA-256, резкость, яркость, источник маркера и его содержимое, полный
`quality_gate`, весь блок `ai` (включая по кадрам).

Нужен, чтобы на защите ответить «а откуда вы взяли GPS?» — открыл и показал.

### 3.7. «🛠️ Ручная верификация экспертом (Human-in-the-Loop)»

Интерактив для демонстрации: можно **вручную переставить** стадию (0/50/100),
материал стен, флаги «нарушение границ», «GPS совпадает», «маркер подтверждён»,
«качество пройдено». Это нужно, чтобы показать ИБ-сценарии: «а что будет, если
инспектор поправит данные?» — ответ: изменится решение, и это уйдёт в аудит.

> Важно: это именно демо-инструмент, в проде такое право должно быть
> разграничено ролями и логироваться.

### 3.8. «📄 Выходной JSON-контракт AI-Агента «Глаз»»

Ровно тот JSON, который описан в ТЗ:

```json
{
  "quality_gate": {"image_quality_passed": true, "exif_gps_match": true,
                   "challenge_marker_present": true, "error_message": null},
  "construction_analysis": {"detected_stage": "100%", "confidence_stage": 0.89,
                            "wall_material": "unknown", "confidence_material": 0.0,
                            "detected_classes": ["roof_finished","walls"],
                            "analysis_source": "sber_yolo_onnx_series",
                            "needs_manual_review": false},
  "geospatial_check": {"boundaries_violation": false, "vri_compliant": true,
                       "site_development_notes": "…"}
}
```

### 3.9. «🛡️ Паспорт снимка / Chain of Custody» и кнопка «Скачать паспорт JSON»

Показывает паспорт целиком и позволяет скачать его файлом. Ссылка «Проверка
паспорта» — адрес, по которому контрагент мог бы проверить паспорт (в демо —
заглушка `stroykontur.local/verify/…`).

### 3.10. «🗺️ Посадка объекта на карте»

Появляется, если есть GPS: одна точка на карте по координатам **из EXIF**.
Это визуализация, а не проверка: карта не подтверждает, что снят нужный участок.

## 4. Правая колонка: «AI-Дирижёр»

### 4.1. Цветная плашка стратегии

| Цвет | Стратегии | Смысл |
|---|---|---|
| 🟢 зелёный (`st.success`) | 1 | всё хорошо, плановый мониторинг |
| 🟡 жёлтый (`st.warning`) | 2, 3, 4, 5, 7 | требует действий, но не катастрофа |
| 🔴 красный (`st.error`) | 6, 8 | фрод/СУБ или взыскание/торги |

### 4.2. «Обоснование ИИ (Explainable AI)»

Один абзац, почему выбрана именно эта стратегия: с какой уверенностью, что
нашли, какие сроки, есть ли просрочка. Это ответ на «почему система так решила».

### 4.3. «🛡️ Доказанность снимка»

Уровень `strong / medium / weak / none` + причина:

* `strong` — GPS + настоящий QR-маркер задания;
* `medium` — GPS + EXIF (демо-режим, QR не найден);
* `weak` — только GPS или только маркер;
* `none` — ничего.

Именно этот уровень решает, назовём ли мы снимок без GPS «фродом» или отправим
человеку.

### 4.4. «Черновик SMS / Push клиенту»

Готовый текст сообщения под выбранную стратегию (его правит и отправляет
сотрудник, автоматической рассылки нет).

### 4.5. «📄 Выходной JSON-контракт AI-Дирижёра»

```json
{
  "verdict": {"strategy_number": 7, "strategy_name": "СТРАТЕГИЯ 7: …"},
  "explanation": "…",
  "client_message_draft": "…",
  "evidence": {"level": "strong", "reason": "…", "gps_confirmed": true, "marker": "qr"}
}
```

### 4.6. «📝 Автоформирование Акта проверки имущества (Приложение 1)»

Форма — точная копия банковского акта осмотра:

| Поле | Откуда предзаполняется |
|---|---|
| Дата и время осмотра | из EXIF снимка (`captured_at`) |
| Кадастровый номер ЗУ | из реестра |
| Адрес объекта | из реестра |
| Зафиксированная стадия ИЖС | из «Глаза» |
| Материал наружных стен | из «Глаза» (сейчас `unknown` → «Не определен») |
| При осмотре установлено (дефекты) | текст из `site_development_notes` |
| Состояние имущества | «Удовлетворительное», если стадия ≠ 0 % |

Кнопка **«🚀 Зафиксировать решение и выгрузить Акт в АС «Калита»»**:

1. берёт SHA-256 снимка (или паспорта);
2. пишет запись в `audit_trail.jsonl` (append-only, с `hash_prev` и `record_hash`);
3. показывает `record_id`, `hash_prev`, `record_hash`;
4. для стратегий 6/8 **не выгружает акт**, а предупреждает: сначала ручной разбор.

> В демо «выгрузка в АС Калита» — это сообщение об успехе. Реальной интеграции
> нет, и на защите это надо сказать прямо.

## 5. Сайдбар (левая тёмная панель)

| Элемент | Что делает |
|---|---|
| **Выберите объект из Реестра (34 участка)** | выбор строки; ниже всё считается по ней |
| **Карточка кредитного досье** | адрес, кадастровый №, старт стройки, плановая дата, ПЗ, регистрация/залог — читаются из реестра |
| **Клиент выходит на связь** | галочка; влияет на выбор между «доп. финансирование» и «замена обеспечения» |
| **Тест сценария ПЗ** | подменяет `Наличие ПЗ` для демонстрации разных веток без правки Excel |
| **Gemini API Key** | внешний VLM; по умолчанию **выключен**, нужен `ALLOW_EXTERNAL_VLM=1` |
| **QR-маркер полётного задания** | ожидаемое значение; по умолчанию `STROYKONTUR-DEMO-2026`; пусто = принимать любой QR |
| **AI: YOLOv8n SberStroi (ONNX) подключён** | статус модели и её наличие |
| **Audit Trail: цепочка цела (N записей)** | текущее состояние журнала |
| **Проверить целостность журнала** | кнопка: пересчитывает всю цепочку хэшей; если файл правили — покажет ошибку |
| **Журнал: `audit_trail.jsonl` · SHA-256 hash chain · append-only** | где лежит журнал и как устроен |

## 6. Страница «🔬 Песочница» (отдельная, в сайдбаре)

Это не банковский процесс, а инструмент проверки:

* загрузка файла, серии или **ссылки из интернета**;
* источник GPS + независимые проверки (WGS-84, активный фикс, расхождение EXIF/XMP);
* Quality Gate;
* рамки детектора на картинке + белая рамка «зона объекта»;
* итоговый вердикт «авто / к инспектору».

Зачем: любой скептик может загрузить своё фото и увидеть, что система не врёт
(«GPS не найден», «доказанность weak», «решение не принимается»).

## 7. Что происходит «под капотом» при нажатии кнопки

1. Файл → SHA-256 (отпечаток).
2. EXIF/XMP → GPS + дата + модель дрона (или «нет»).
3. Quality Gate: резкость, яркость, координаты.
4. QR-маркер: ищем в кадре, сверяем с ожидаемым.
5. Нейросеть по всем кадрам → стадия + уверенность + доказанность.
6. «Дирижёр» → стратегия + объяснение + SMS.
7. Паспорт снимка → JSON.
8. Кнопка «Зафиксировать» → запись в журнал аудита.

---

## 8. Чего в интерфейсе нет (не выдумывай на защите)

* Нет аутентификации и ролей — любой, у кого открыт браузер, видит всё.
* Нет реальной интеграции с АС «Калита» — только демонстрационная кнопка.
* Нет загрузки реестра из банковской системы — читается локальный Excel.
* KPI вверху — статичные цифры из кейса.
* Карта — просто точка из EXIF, без проверки кадастровых границ.
* Материал стен всегда `unknown` — модель его не определяет.
