# Протокол съёмки и полётное задание

Кейс прямо просит: «Периодичность, параметры съёмки и т.д. — предлагаем
проработать в рамках хакатона». Это ответ. Без одинаковых параметров кадры
нельзя сравнивать между вылетами, а значит и стадию отслеживать нельзя.

---

## 1. Зачем протокол

Модель и человек сравнивают «сейчас» с «прошлым разом». Если каждый вылет
делается с разной высоты, ракурса и в разное время суток, сравнение ломается:
крыша «меняется» из-за света, а не из-за стройки.

Протокол фиксирует: **высоту, ракурсы, перекрытие, время, состав кадров и
маркер** — чтобы кадры были сопоставимы, а результат воспроизводим.

---

## 2. Параметры съёмки (рекомендуемые)

| Параметр | Значение | Зачем |
|---|---|---|
| Высота основного облёта | **40–60 м** | компромисс: видно дом и соседей, GSD ≈ 1,0–1,6 см/пиксель |
| Ракурсы | **надир (90°)** + **наклонный (45°)** | надир — крыша и контур; наклон — стены, окна, двери |
| Перекрытие кадров | **70 % по маршруту / 60 % между галсами** | чтобы дом точно попал в кадр и не было «дыр» |
| Маркерный кадр | **8–12 м**, маркер в кадре | QR читается только с близкого расстояния (см. `QR_MARKER_DESIGN.md`) |
| Время съёмки | **10:00–16:00**, высота солнца > 30° | длинные тени искажают геометрию |
| Погода | ветер **< 8 м/с**, без осадков, видимость > 5 км | смаз и блики |
| Объём серии | **8–20 кадров** на объект | хватает для слияния; больше — дольше обработка |
| Формат | JPG/PNG, **оригиналы** (не из мессенджера) | мессенджеры стирают EXIF |

**GSD (сколько сантиметров земли в пикселе)** для камеры DJI M3M (4/3", 5280 px,
фокус ~12,3 мм):

```
GSD (см/пиксель) ≈ 0,027 × высота_м
```

| Высота | GSD | Что различимо |
|---|---|---|
| 20 м | 0,53 см | окна, двери, дефекты |
| 40 м | 1,07 см | окна, двери |
| 60 м | 1,60 см | контур, кровля, крупные элементы |
| 100 м | 2,67 см | только контур и крыша |

---

## 3. Периодичность

| Событие | Когда снимаем |
|---|---|
| Плановый контроль | **1 раз в квартал** (4 раза в год) |
| Выдача очередного транша | перед выдачей |
| Появление просрочки (ПЗ) | в течение 10 рабочих дней |
| Истечение плановой даты | за 30 дней до и после |
| Спорный случай / жалоба клиента | вне графика |

Это ориентир для пилота; финальные сроки — за бизнесом.

## 4. Полётное задание (JSON) — что передаётся подрядчику

```json
{
  "task_id": "FT-2026-11-01-001",
  "object": {
    "cadastral_number": "54:19:133701:2991",
    "address": "Новосибирская обл, Новосибирский р-н, п Ложок",
    "polygon_wgs84": [[54.8511, 83.1946], [54.8512, 83.1948], [54.8510, 83.1949], [54.8509, 83.1946]]
  },
  "window": {"from": "2026-11-01T10:00:00+07:00", "to": "2026-11-01T16:00:00+07:00"},
  "drone": {"model": "DJI M3M", "serial": "…"},
  "operator": {"contractor_id": "C-014", "pilot_id": "P-07"},
  "survey": {
    "altitude_m": 50,
    "angles": ["nadir", "oblique_45"],
    "overlap_forward_pct": 70,
    "overlap_side_pct": 60,
    "frames_expected": 12,
    "marker_frame_altitude_m": 10
  },
  "marker": {
    "payload": "SC1|FT-2026-11-01-001|54:19:133701:2991|1730000000|a7f31c9e|8f1c…",
    "expires_at": "2026-11-01T18:00:00+07:00",
    "nonce": "a7f31c9e"
  },
  "geozone": {"center": [54.8511, 83.1946], "radius_m": 150},
  "required": ["originals", "exif", "marker_frame"]
}
```

Зачем каждое поле:

* `polygon_wgs84` — сверить, что координаты кадров внутри участка (а не соседа);
* `geozone` — грубая проверка «дрон был здесь», защита от чужого вылета;
* `marker` — одноразовый код и срок;
* `survey` — чтобы кадры были сравнимы между вылетами;
* `required` — что подрядчик обязан передать (оригиналы, EXIF, маркерный кадр).

---

## 5. Что проверяет система при приёме серии

| Проверка | Как | Если не прошло |
|---|---|---|
| Файлы оригинальные | есть EXIF дрона, нет следов пересжатия | `weak` → повторный вылет |
| Внутри геозоны | GPS кадров в радиусе | `weak` |
| Высота и ракурс | EXIF `GPSAltitude`, оценка угла | предупреждение |
| Размытость | Laplacian < 120 | кадр брак |
| Перекрытие | оценка по перекрытию кадров | запрос досъёмки |
| Маркер | декодирование QR + подпись + TTL | `medium`/`weak` |
| Минимум кадров | ≥ 8 | запрос досъёмки |

---

## 6. Что делать, если летать нельзя

Из кейса: «Ждать, когда будет можно!». Практически:

1. **Перенос** в окно по погоде, с фиксацией причины в аудите.
2. **Съёмка с земли** — как временная мера, с пометкой «не аэро»: стадия может
   быть занижена (модель обучена на надирных кадрах).
3. **Архив прошлого вылета** — только с явной пометкой «данные не свежие» и
   понижением уровня доказанности.

## 7. Ответ на защите (20 секунд)

> «Мы фиксируем протокол: надир 40–60 метров плюс наклонный ракурс, перекрытие
> 70/60, съёмка 10:00–16:00, отдельный кадр с маркером с 8–12 метров. Это даёт
> GSD около сантиметра — видно окна и двери, и кадры сравнимы между вылетами.
> Периодичность: раз в квартал плюс событийно — транш, просрочка, истечение
> срока. Всё это уходит подрядчику как полётное задание в JSON, вместе с
> одноразовым маркером и геозоной».
